Wie done / fail funktionieren

Die Engine prüft beide Bedingungen jeden Frame, solange das Segment läuft:

Wirkung
done Segment geschafft → Split wird gespeichert, nächstes Segment startet. Wird VOR fail geprüft — treffen beide im selben Frame zu, gewinnt der Erfolg.
fail Segment-Neustart: Savestate des Segment-Anfangs wird neu geladen — die Gesamtzeit läuft weiter (kein Run-Reset!). Den kompletten Run von vorn gibt es nur über die Reset-Combo des Spielers.
Neu — mehrere fail-Bedingungen: fail (und auch done) akzeptiert jetzt eine Liste von Bedingungen — es reicht, wenn eine zutrifft (ODER-Logik). Beispiel: Tod oder Start+Select sollen beide das Segment neu starten. Challenges, die die Listen-Form nutzen, brauchen die nächste Engine-Version — dann min_version in games.lua entsprechend setzen.

Verfügbare Operatoren (op) — „Basiswert" = der Wert der Adresse beim Versuchs-Start:

oplöst aus, wenn …
nonzeroder Wert ≠ 0 ist (Standard, wenn kein op angegeben)
increasedder Wert größer als der Basiswert ist
decreasedder Wert kleiner als der Basiswert ist
changedder Wert vom Basiswert abweicht
equalsder Wert exakt value entspricht
atleastder Wert ≥ value ist
increasedbyder Wert seit Versuchs-Start um mind. value gestiegen ist (z. B. „sammel X Coins" — zählt ab dem Stand beim Segment-Start)
decreasedbyder Wert seit Versuchs-Start um mind. value gefallen ist
Neu: increasedby/decreasedby brauchen die nächste Engine-Version — Challenges, die sie nutzen, entsprechend min_version in games.lua setzen.
Hinweis: Gelesen wird SNES Work-RAM — addr = 0x1493 entspricht $7E:1493. Optional size = 2 für 16-Bit-Werte (Standard: 1 Byte).
Ohne Adresse: done = { kills = 10 } nutzt statt einer RAM-Adresse den Gegner-Zähler der Engine („töte 10 Gegner", Details in der Nachschlagliste unten). Braucht die Engine-Version mit Zähler-Support (3.0+) → min_version setzen.
Fortschritt im HUD: Bei atleast, increasedby und decreasedby blendet die Engine automatisch aktueller Wert / benötigter Wert ein (z. B. „Score 1200/5000") — praktisch für alles, was das Spiel selbst nicht anzeigt. Pro Bedingung optional: label = "Score" (Beschriftung), mul = 10 (Anzeigefaktor, falls der RAM-Wert skaliert ist) und show = false (nie anzeigen). Für bekannte Adressen ($0F34 Score, $0DBF Coins, $18D2 Combo, $0DBE Leben) sind Beschriftung und Faktor schon hinterlegt. nonzero/equals/Bitmasken haben keinen Zwischenstand → keine Anzeige. Ab Engine 3.0.

Nachschlagliste: die wichtigen Adressen

Verifiziert gegen die SMWCentral-RAM-Map (SMW US).

EreignisAdresseBedingung für games.luaDetails
done Goal-Tape / Orb / Boss $7E:1493 { addr = 0x1493, op = "nonzero" } End-Level-Timer: läuft, sobald das Zielband berührt / der Orb eingesammelt / der Boss besiegt wurde. Deckt alle „normalen" Level-Enden ab — die Standard-Erfolgsbedingung.
done Nur Orb (Goal Sphere) $7E:1493 { addr = 0x1493, op = "equals", value = 0xFF } Der Orb setzt den Timer direkt auf 0xFF. Nur nötig, wenn das Level auch ein Zielband hat und wirklich NUR der Orb zählen soll.
done Keyhole (Schlüsselloch) $7E:1434 { addr = 0x1434, op = "nonzero" } Keyhole-Sequenz-Timer: wird beim Aktivieren auf 0x30 gesetzt.
done Checkpoint (Midway) $7E:13CE { addr = 0x13CE, op = "increased" } Midway-Flag: 0 → 1 beim Durchqueren. Bewusst increased statt nonzero: falls der Start-Savestate das Flag schon gesetzt hat, feuert die Bedingung nicht sofort.
done Level verlassen (geschafft) $7E:0DD5 { addr = 0x0DD5, op = "equals", value = 0x01 } Wie das Level beendet wurde: 0x01 = normaler Exit, 0x02 = Secret Exit (Keyhole-Ausgang). Feuert erst beim Level-Unload — später als $1493/$1434. Für Splits „auf dem Band" die Timer-Adressen nehmen.
done X Coins sammeln $7E:0DBF { addr = 0x0DBF, op = "increasedby", value = 20 } Coin-Zähler (0–99). increasedby zählt ab dem Coin-Stand beim Segment-Start — also „value" Coins einsammeln, egal womit das Segment startet. Vorsicht 100er-Grenze: bei 100 Coins gibt's ein 1-Up und der Zähler springt auf 0. value so wählen, dass diese Grenze im Segment nicht überschritten wird.
done X Score-Punkte erzielen $7E:0F34 { addr = 0x0F34, op = "increasedby", value = 500, size = 3 } Mario-Score (3 Bytes). Der RAM-Wert ist Punkte ÷ 10 — value = 500 heißt also 5000 Punkte. SMW blendet den Score während des Levels nirgends ein — die Engine zeigt ihn deshalb als Fortschritt im HUD: „Score 1200/5000" (Adresse $0F34 ist bekannt, der Faktor 10 wird automatisch eingerechnet). size = 3 liest genau die drei Score-Bytes; ältere Snippets mit size = 4 funktionieren weiter (das vierte Byte ist Luigis Score-Low-Byte, bei increasedby egal).
done X Gegner töten $7E:14C8 { kills = 10 } Gegner-Zähler der Engine: sie scannt pro Frame die Sprite-Statustabelle ($14C8, 12 Slots) und zählt jeden Wechsel von „lebt" (08 normal, 09 liegend, 0A gekickt, 0B getragen) auf „tot" (02 weggeschleudert, 03 platt, 04 Spinjump, 05 verbrannt); von Yoshi verschluckt (07 → 00) zählt ebenfalls. Der Zähler startet bei jedem Versuch wieder bei 0 (der Savestate bringt die Gegner ja auch zurück) und wird im HUD als „Kills 3/10" eingeblendet. Normales Despawnen am Bildschirmrand zählt nicht. Pro Segment abschaltbar/anpassbar über kills = false bzw. kills = { label = "Gegner", ... }.
fail Death (Tod) $7E:0071 { addr = 0x0071, op = "equals", value = 0x09 } Player-Animation: 0x09 = Death-Animation. Feuert sofort im Moment des Todes — der Neustart kommt ohne „MARIO START!"-Umweg.
fail Start+Select-Exit $7E:0DD5 { addr = 0x0DD5, op = "equals", value = 0x80 } Level per Start+Select verlassen setzt 0x80. Achtung: Auch ein Tod setzt am Ende der Death-Animation 0x80 — in Kombination mit der Death-Bedingung feuert die aber vorher (unproblematisch). Ohne Death-Bedingung fängt diese hier beides ab, nur später.
